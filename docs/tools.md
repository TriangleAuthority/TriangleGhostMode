# Tools

`<game>` and `<REDkit>` stand for the install folders of The Witcher 3 and of REDkit. The tools find them through Steam, or take them from the `W3_GAME_DIR` and `W3_REDKIT_DIR` environment variables (`tools/paths.py`). No absolute paths go into the repository: tools and docs use relative paths, these placeholders or environment variables.

## Project tools (`tools/`)

Plain Python 3 (tested with 3.13); no extra packages needed.

**Parallel ports** ([proposal](proposals/parallel-ports.md)): every generator and check takes a **required** `--worktree DIR` (the area's `..\TGM-<area>`, or `.` for the main checkout), and `build_mod.py` a required `--ref` and `--out`, so no tool reads, writes or builds another area's branch by default. They run at below-normal CPU priority. The game is one slot: `game.py`'s state-changing commands and `build_mod.py`'s installs need `--holder AREA:TOKEN` from `game_lock.py` ([game-automation.md](game-automation.md#the-game-slot)), and run from the main checkout's `tools/` (the only copy with rw3d_cli).

**Generators** share a form: they write Ghost Mode's DLC files (or whole-file overrides under `modGhostMode/files/`) in the given worktree from the `vanilla-1.32`, `legacy-GM` and `vanilla-5.x` branches and `docs/features/attribution.csv`; `--check` writes nothing and fails if a file is out of date; `--verify` writes nothing and compares what the game reads (Ghost Mode's DLC over 5.x, `extend` entries resolved, regular and NG+ folders) with legacy's or the port's intended values, and fails on any unexplained difference or a name defined twice in a DLC folder. Lists in the scripts (`SPEC`, `PORTED`, `KEEP_5X`, `LATER`, `OWNED`, ...) say what is ported so far; each script's docstring has the details. `gen_all.py` runs them in order.

### Inspection and extraction

| Script | Purpose |
|---|---|
| `paths.py` | Finds the game and REDkit install folders for the other tools: `W3_GAME_DIR` / `W3_REDKIT_DIR` if set, else Steam (the Steam folder from the registry or `STEAM_DIR`, its libraries, each app's manifest). Run it to print what it finds. Also shared: `documents_dir()` (Documents, following OneDrive), `add_worktree(ap)` (the required `--worktree`, checked to hold `modGhostMode/`) and `below_normal()`. |
| `extract_vanilla.py <out_dir> [--utf8] [--game DIR]` | Extracts the vanilla file set (all scripts, gameplay XML/CSV, and every other file under `modGhostMode/files`) from a legacy or 5.x install into `<out_dir>/scripts` and `<out_dir>/files`, in pure Python (no REDkit). Both committed baselines regenerate byte-for-byte. Keeps the game's encodings unless `--utf8` (use it for legacy). A few seconds. |
| `unbundle.py <bundle-or-dir> <out_dir> [--list]` | Extracts every file from `.bundle` files in pure Python: legacy and 5.x game bundles and packed mods (`content\blob0.bundle`). Supports every compression the game uses: stored, zlib, Doboz (legacy) and LZ4/LZ4HC. |
| `port_status.py [--mod REF] [--new REF] [--out FILE]` | Compares the legacy vanilla files on `vanilla-1.32`, `legacy-GM` and `vanilla-5.x`, and writes [5.x-file-status.md](5.x-file-status.md): per-file 5.x status and dry-run merge result for every Ghost Mode file. Re-run after a new game version lands on `vanilla-5.x`. |
| `cr2w_dump.py <file>` or `cr2w_dump.py --rev <ref> <path>` | Dumps a binary CR2W resource (`.w2ent`, `.journal`, `.w2scene`, ...) as readable text: every object and property, including embedded and compiled sub-files and a scene script block's call parameters (`params (after properties):`). Reads legacy (162/163) and 5.x (164) files; read-only. Also git's text converter for these files ([Git and GitHub](#git-and-github)). |
| `cr2w_patch.py FILE EDIT [...] [--check]`, `--roundtrip FILE [...]`, `--selftest` | Edits a CR2W file. `CLASS.PATH=OLD:NEW` sets a property (integer, float, CName, enum or String; a dotted path through struct fields and arrays of structs, `containers[name=X].chance` selects entries); `CLASS.PATH-=VALUE` removes a property or array entries (`-=*` whatever its value); `CLASS.PATH+=VALUE` appends an array entry (structs as `FIELD=V,...` or `FIELD:TYPE=V,...`); `CLASS.PATH:TYPE+=VALUE` adds a missing property; `CLASS#N` edits only the class's Nth chunk; a path starting with `@` edits a parameter of a scene script block's call. Every chunk of the class is edited, also in embedded CR2W copies (`flatCompiledData`). Same-size number edits are written in place; others rebuild sizes, offsets, string and name tables and every CRC. Refuses a file with inconsistent CRCs, or rebuilding one with buffers or embedded-file tables. Functions for cooked files (used by `gen_sword_glows.py`): `patch_bytes`, `repoint_imports`, `cooked_effects`, `clone_cooked_effect`. `--roundtrip` rebuilds files unchanged and compares (all of `vanilla-5.x`'s binary files come back byte for byte); `--selftest` checks the encodings, known scene edits and, with the game installed, the cooked-file functions. See [binary-files.md](binary-files.md#porting-them-to-5x). |
| `bindiff.py BASE OTHER [PATH ...] [--summary] [--keep-noise]` | Property-level diff of every binary file that differs between two refs, with re-save noise filtered out. `bindiff.py vanilla-1.32 legacy-GM` shows Ghost Mode's binary edits; `bindiff.py vanilla-1.32 vanilla-5.x` shows CDPR's. See [binary-files.md](binary-files.md). |
| `exec_catalog.py [--ref REF] [--out FILE]` | Lists every vanilla `exec function` (console command) on `vanilla-5.x` with its signature, first statement and source line, grouped by topic, into [console-commands.md](console-commands.md). Tested commands are marked from its `VERIFIED` set. Re-run after a new game version lands. |
| `change_units.py [--filter PATTERN]` | Inventories Ghost Mode's changes as change units (script functions and class members, XML entries, CSV rows, binary files) and compares each across legacy vanilla, the `legacy-GM` commits and `vanilla-5.x`. Writes `docs/features/units.csv` and, with `docs/features/attribution.csv`, `docs/features/coverage.md`. About 30 seconds; `--filter "*Cooldown*"` prints matching units instead. Script units are compared without comments but with string and name literals. **It cannot see a change to a class's or state's declaration line** (parent class, `import class`); known cases under [units.csv](feature-mapping.md#unitscsv-generated). See [feature-mapping.md](feature-mapping.md#layout). |
| `unit_sweep.py PATTERN [--unattributed] [--type ws\|xml\|all] [--lines N] [--case-sensitive]` | Lists every change unit whose Ghost Mode change adds or removes a line matching PATTERN, with its attribution and 5.x status. Used to check an area's mapping before calling it complete ([feature-mapping.md](feature-mapping.md#feature-ids-and-areas)). About a minute. |
| `econ_prices.py [--items [RE] \| --rewards \| --tags \| --units]` | Compares every item's `price` and `mod_*` price tags and every reward's `gold` across `vanilla-1.32`, `legacy-GM` and `vanilla-5.x` (all games and folders, not Ghost Mode's DLC): a summary by file and category, or one line per item, reward, tag change or unit key. Read-only, about 40 seconds ([econ.md](features/econ.md)). |

### Checks

| Script | Purpose |
|---|---|
| `check_modsigns.py --worktree DIR [--verbose]` | Checks Ghost Mode's scripts against `vanilla-5.x`: every `@replaceMethod` body and scope-based override must mark each change with `//modSigns` (at the end of added or changed lines; a removal by a comment where the code was); alarms on any `@wrapMethod` of a native function. Shows exactly which lines are unmarked. Exits 1 on a finding. About 2 seconds. Run it before committing script changes ([development.md](development.md#conventions)). |
| `dlc_conflicts.py --worktree DIR` | Lists every `<item>`, `<ability>` and `<item_extension>` entry in Ghost Mode's DLC definition folders without `on_conflict` on a name `vanilla-5.x` already defines in the same kind of folder (the game ignores such an entry, [development.md](development.md#fine-grained-xml-overrides-50)); and every `<base_abilities>` reference of a DLC item that neither 5.x nor the DLC defines in the same game's folders (a reference 5.x's own entry also makes is listed, not failed). Exits 1 on a finding. About 15 seconds; `gen_econ.py --verify` runs it too. |
| `deviations.py [--unconfirmed] [--write] [--check]` | Lists every recorded deviation from legacy (the `- **Deviation:**`, `- **Deviation (new tree):**` and `- **New design:**` bullets, [convention](feature-mapping.md#legacy-behaviour-first)), grouped by feature; `--unconfirmed` only those the owner has not confirmed; `--write` regenerates `docs/features/deviations.md` (classic tree) and `docs/features/deviations-new-tree.md` (new tree only); `--check` fails when either is out of date. |

### Build and game

| Script | Purpose |
|---|---|
| `build_mod.py --ref REF --out DIR [--install --holder AREA:TOKEN] [--enable] [--release] [--loose] [--base REF] [--scripts DIR]`, `build_mod.py --install-from DIR --holder AREA:TOKEN` | Builds an installable mod from a branch: compiles every script the branch adds or changes relative to `vanilla-5.x` with `wcc_lite compilescripts` (about 20 seconds, log in `<out>/compile.log`) into `<out>/modGhostMode/content/precompiled.rsblob`; a compile error stops the build, and so does a ref that changes vanilla scripts relative to `--base` (a new release's vanilla commit is not on `vanilla-5.x` yet, [repository.md](repository.md#keeping-branches-up-to-date)). Packs changed game files under `modGhostMode/files/` (`wcc_lite pack`, `blob0.bundle` and `metadata.store`), encodes `modGhostMode/localization/` CSVs (`w3strings.py`) and packs `modGhostMode/sound/` banks (`soundcache.py`). Without `--install` it is the compile-only build; `--install-from DIR` installs such a build later. Installing copies the mod into `<game>\mods\modGhostMode` and the menu XML into `<game>\bin\config\r4game\user_config_matrix\pc\`, needs the game slot's `--holder` (or `--parent`) and the game closed, and records the build in the lock for `game.py start`. `--enable` adds it to `mods.settings`; `--release` leaves out the in-game tests; `--loose` ships loose scripts (experiments only); `--scripts DIR` builds a folder of scripts (used for `modAutomation`; installing one needs `--parent`). Each `wcc_lite` run holds `%LOCALAPPDATA%\TGM\wcc.lock` (it writes REDkit's log, script cache, `temp\` and `editoruser.settings`, and listens on port 37000), so parallel builds wait their turn. Warns about uncommitted changes under `modGhostMode/` (the build takes the commit). See [development.md](development.md#build-compile-install). |
| `game.py run\|start\|load\|exec\|resume ... --holder AREA:TOKEN`, `game.py status\|saves\|log\|quit` | Drives the game for automated tests through the test-only `modAutomation` (`tools/automation/`, built with `build_mod.py --scripts`) and rw3d_cli (`tools/rw3d/`, git-ignored download): launch without the launcher, load a save, run exec functions and print their output, report state, quit. `run`, `start`, `load`, `exec` and `resume` need the game slot's `--holder AREA:TOKEN` (`--parent` skips the check and is logged). `run` and `load` take `test` (the test save), `slot` (the test-only slot) or another allowed save by full name, all set per machine with `game_lock.py config` ([test saves](game-automation.md#test-saves)); every load calls `gmtest_nosave()`. `start` refuses a `modGhostMode` the holder did not install this turn; `exec` refuses calls that load or save (`DENIED_EXEC`). Exit 0 on success, 1 on a timeout, error or refusal, 3 when the slot is paused or the token revoked. See [game-automation.md](game-automation.md). |
| `game_lock.py request\|wait\|status\|release\|cancel\|pause\|resume\|config\|preempt\|reclaim\|watch\|baseline\|selftest` | The game slot for parallel ports: one holder at a time, FIFO queue, tokens ([game-automation.md](game-automation.md#the-game-slot)). State in `%LOCALAPPDATA%\TGM\` (`state.json`, `config.json`, `events.log`, `baseline\`, `logs\`), changed under an OS file lock and written through a temporary file and `os.replace`. `request --who AREA --why TEXT` grants (exit 0, prints the token) or queues (2; 3 when paused); `wait --who AREA [--timeout S]` blocks until granted (0), times out (2) or is stopped by a pause or a revoked token (3); `release --holder AREA:TOKEN` (game closed) restores the four settings files from the baseline, archives `scriptslog.txt` under `logs\`, compares the saves with the grant's list and the backup (logs differences, restores nothing) and grants the next; `cancel`, `status [--json]`, `pause`/`resume`. `config --claim-deadline S --lease S` sets the timings; `config --test-save NAME --slot-save NAME [--allow-save NAME ...] [--disallow-save NAME]` sets the saves `game.py` may load on this machine ([test saves](game-automation.md#test-saves)). Parent only (`--parent`): `preempt`, `reclaim` (expired lease), `baseline` (the four settings files, game closed, the owner's OK). `watch` exits 4 with an `ALERT:` line on anything the parent must see. Each grant backs up the saves (`robocopy /E /XO` into `%USERPROFILE%\W3SaveBackup\gamesaves`). `selftest` (`game_lock_selftest.py`) runs offline checks in a temporary folder (`TGM_LOCK_SELFTEST_ROOT`), about 20 seconds. |
| `regress.py --holder AREA:TOKEN [--trees both\|classic\|new] [--save test\|slot\|NAME] [--wait 6000] [--no-retry]` | The regression run ([development.md](development.md#testing-in-game)): per tree a fresh launch of the save (`--save`, default `test`, the configured test save), the tree set by `autoconfigset(GMGameplayOptions, GMClassicSkillTree, ...)` and `gmreset()`, then `gmtest_regress()` (`exec --wait 6000`), `ingamemenu()`, `gmtest_panel()`, resume, the classic tree always set back, quit. Prints each tree's counts (the SUMMARY line, then the PASS and FAIL lines) and archives each script log under `%LOCALAPPDATA%\TGM\logs\`. When only a known timing flake failed (AI-18's stone, AI-10's counter window) it runs that tree once more; a flake counts only when it fails twice in a row. Exit 0 when every tree passed. |
| `enum_sync.py check\|apply\|restore [--mods DIR] [--scripts DIR]`, `patch OUT_DIR BLOB...`, `dump BLOB [FUNCTION]` | Makes blob mods that extend the same enum work together ([development.md](development.md#scripts), enum bullets): gives every installed blob that extends an enum the full member list (all of them, in load order) and renumbers that blob's enum literals to match, by patching the compiled blobs (no decompiling). Literals carry no type, so it infers each one's expected type from the vanilla script declarations and the blobs; a literal of the blob's own members it cannot type stops the run. `apply` keeps the originals (`precompiled.rsblob.enum_sync-original`) and always starts from them; `patch` writes patched copies of the given blobs (in that order) for builds and tests; `dump` lists a blob's enum literals with their inferred types. Usage, method and limits at the top of the file; meant to be shareable (also with Script Merger's author). |
| `focus_game.ps1`, `send_key.ps1`, `mouse_move.ps1`, `screenshot.ps1` | Fallback game control by simulated key presses (scan codes), mouse moves (to hover menu items and show their tooltips) and screenshots. See [game-automation.md](game-automation.md#keyboard-and-screenshot-fallback). |

### File formats

| Script | Purpose |
|---|---|
| `make_reddlc.py <out.reddlc> --id ID --xml PATH [--xml PATH ...] [--xml-ngplus PATH ...]` or `--selftest` | Writes a DLC definition (`.reddlc`, CR2W) whose `CR4DefinitionsDLCMounter`s make the game load the given definitions XML files or folders (depot paths, e.g. `dlc\dlcghostmode\data\gameplay\abilities\`), and whose `CR4DefinitionsNGPlusDLCMounter`s load the New Game+ ones. Not required by saves, hidden from the DLC menu. `--selftest` rebuilds vanilla `dlc8.reddlc` from the REDkit depot byte for byte. See [development.md](development.md#dlc-and-mounters). |
| `w3strings.py encode <in.csv> <out.w3strings>`, `decode <in.w3strings> <out.csv>`, `--selftest` | Encodes and decodes string tables in pure Python, in the 5.0 format (version 164, UTF-8 text) or the legacy one (162, UTF-16), using the community encoder's CSV format. `--selftest` decodes all of the game's 5.0 string tables and re-encodes them byte for byte. Decoding the game's tables finds a vanilla string's id. See [development.md](development.md#localization). |
| `soundcache.py list\|extract <cache> [out_dir]`, `pack <out.cache> <file>...` | Reads sound caches (`soundspc.cache`, `CS3W`) in formats 1 (legacy) and 2 (5.x), and writes format 2: a 64-byte header, the files from 0x40, the names, then the table (u64 name offset, data offset, size); the header's checksum is FNV-1a 64 over the names followed by the table. See [development.md](development.md#sound-banks). |
| `rsblob.py <blob> [FUNCTION\|*]` | Reads and writes script blobs (`precompiled.rsblob`) in pure Python, byte for byte (**verified** on blobs built by `wcc_lite` and `WSCompiler`, Ghost Mode's 2.5 MB one included), and decodes function bytecode into instructions and expression trees (every function of Ghost Mode's blob decodes completely). Run alone it prints a blob's sections and enum extensions, with a function name its disassembly. The format is described at the top of the file (written from the description in Aelto's tw3-cahirb `rsblob_disas.py`, no code taken). Used by `enum_sync.py`. |
| `ws_decls.py` | Collects declarations (enums with values, classes, states, structs, fields, function signatures) from WitcherScript sources and blobs, with types in the blobs' spelling; `enum_sync.py`'s type inference. |
| `to_utf8.py <dir-or-file>...` | Converts UTF-16/BOM text files (`.ws .xml .csv .txt`) to plain UTF-8 in place and fixes `encoding="UTF-16"` declarations. Used for the legacy baseline. Do not use it on files meant for 5.0, which expects a BOM on XML. |

## Game install

`<game>` (5.x, Steam app 292030; the project's baseline is Steam build 26238013, `witcher3.exe` 5.0.0.1090142). Everything, the expansions and DLCs included, is in `content\content0`; there is no `dlc` folder (`dlc-tombstones\` holds empty markers) and a fresh install has no `mods` folder.

**Legacy (1.32) game files:** a copy of a legacy install kept outside the repository (`<legacy game>`; `witcher3.exe` 3.0.0.1259521, the legacy layout: `content\content0`–`12`, `patch0`, `patch1`, `DLC\*`). It is the source for legacy vanilla files, e.g. `tools/unbundle.py` on its bundles or `python tools/extract_vanilla.py <out> --utf8 --game "<legacy game>"`, which reproduces the legacy baseline on `vanilla-1.32` exactly.

- Scripts are loose files in `content\content0\scripts` (`core`, `engine`, `game`).
- Everything else is in `content\content0\bundles\*.bundle`. `xml.bundle` holds most engine XML; gameplay XML is spread across `blob.bundle`, `bob.bundle`, `ep1.bundle`, `dlc0.bundle`, `startup.bundle` and the `world_*` bundles. [game-5.0-changes.md](game-5.0-changes.md) describes the bundle format.
- Menu configs: `bin\config\r4game\user_config_matrix\pc\*.xml`.
- String tables: `content\content0\<lang>.w3strings`.

## The Witcher 3 REDkit (CDPR's official mod tools)

`<REDkit>` (Steam app 2684660; Steam build 26269436, `wcc_lite` 5.0.1090143, matching game build 1090142; `bin\wcc.log`'s first line names the build). Docs: [REDkit wiki](https://cdprojektred.atlassian.net/wiki/spaces/W3REDkit/pages/6324268/General+information); [development.md](development.md) summarizes what matters for this project. The wiki pages render with JavaScript, so fetch their text through the Confluence REST API instead: `https://cdprojektred.atlassian.net/wiki/rest/api/space/W3REDkit/content/page?limit=100&expand=body.view` lists every page with its content.

Steam updates REDkit in place, so older builds are not kept: the 5.0 update replaced the `wcc_lite` that could read legacy bundles. The project's extraction tools do not depend on it. An older build would have to be fetched with Steam's depot downloader (`download_depot` in the Steam console, with an old manifest ID).

| Path | What it is |
|---|---|
| `bin\x64_RedKit\editor.exe` | The REDkit editor: opens and edits resources (entities `.w2ent`, quests, scenes, ...). |
| `bin\x64_RedKit\scriptStudio.exe` | Script editor/debugger for `.ws` scripts. |
| `bin\x64_RedKit\wcc_lite.exe` | Command-line cooker and packer (see below). |
| `bin\x64_RedKit\bundlebuilder.exe`, `bin\tools\cooker\do_game.bat` | Bundle building and cooking pipeline. |
| `r4data\` | Uncooked game depot (about 66 GB): editable source versions of game resources, apparently matching the current game (XML in UTF-8 with BOM). Another source of vanilla 5.0 files. |

### wcc_lite

Run it from `bin\x64_RedKit` with no arguments to list commands, or `wcc_lite <command>` for a command's usage. Commands useful here:

| Command | Use |
|---|---|
| `compilescripts <scripts dir>\ -patch=<mod scripts dir>\ -out=<path>` | New in 5.0. Compiles the game's scripts (`<game>\content\content0\scripts\`) plus a mod's, and writes the mod's compiled scripts as a script blob (`<path>\blob.rsblob`). Exit code 1 and `[Error][WCC] [<line>]: <message>` lines on errors. About 20 seconds. `tools/build_mod.py` runs it as its compile check. Directory arguments need a trailing backslash. |
| `unbundle -dir=<bundles dir> -outdir=<dir>` | Extracts **every** file from every bundle in a directory (recursive). There is no filter option. Since the REDkit update for 5.0 it only reads 5.x bundles: legacy ones fail with "invalid headerVersion: 3 (expected 5)". Use `tools/unbundle.py` instead. |
| `uncook -indir=<bundles dir> -outdir=<dir> [-unbundleonly]` | Extracts and uncooks resources (e.g. textures to `-imgfmt=tga`). |
| `pack -dir=<dir> -outdir=<dir> [-compression=LZ4\|LZ4HC\|ZLIB]` | Packs a directory into a bundle (for building the mod). |
| `metadatastore` | Generates `metadata.store` for a directory of packed bundles (needed when shipping a mod; run `wcc_lite metadatastore` for its arguments). |
| `cook`, `import`, `export` | Cooking and asset import/export. |
| `dumpfile -file=<path> -out=<file>` | Documented as dumping a resource's objects to text. Produces no output on a legacy `.w2ent`. |
| `dumpbundleinfo -indir=<path> -outpath=<path>` | Lists bundle contents. Rejects `-outpath` ("No out file path"). |

Gotchas: commandlets can open a blocking EULA dialog (it has no "remember" option, and the `DoNotShowEula` registry value under `HKCU\Software\CD Projekt RED\Mod Tools\1.0` does not stop it); pass `-agreetoterms` to skip it, as `build_mod.py` does (the project owner accepted the EULA and approved this). Pass absolute Windows paths. Output paths over 260 characters fail ("Unable to create output file"), so extract to a short directory (e.g. one at the drive root). Unknown options are silently ignored.

## Git and GitHub

- Contributors commit with their own git identity; nothing in the repository depends on a particular account or remote setup.
- `core.autocrlf=true` and `* text=auto`: text is stored with LF and checked out with CRLF (see [repository.md](repository.md)).
- **Readable diffs of binary files**: `.gitattributes` assigns a `cr2w` diff driver to `.w2ent`, `.journal`, `.w2scene`, `.w2phase`, `.w2beh`, `.w2behtree` and `.w2comm`. Git config is not versioned, so enable it once per clone:

  ```bash
  git config diff.cr2w.textconv "python tools/cr2w_dump.py"
  git config diff.cr2w.cachetextconv true
  ```

  Then `git diff`, `git show` and `git log -p` print these files through `tools/cr2w_dump.py` as indented text (e.g. `git diff vanilla-1.32...legacy-GM -- <file.w2ent>`). Notes: the files stay binary in the repository; GitHub's web view and `git diff --stat` still say "Bin"; merges still treat them as binary; `--no-textconv` shows the raw "binary files differ". Re-save noise (CR2W version, regenerated proxy GUIDs, cooked effect buffers) appears in these diffs; `tools/bindiff.py` filters it.
