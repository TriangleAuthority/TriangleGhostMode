## [DEF-05 Parrying rules](def.md#def-05-parrying-rules)

- a parry without enough stamina of a parryable attack (STAM-03) staggers. Legacy added the stagger, but vanilla's `ProcessActionBuffs` applies no effect of a parried hit of a parryable attack, in legacy too, so it never applied: a defect against the changelist's partial parry (project owner, 2026-10-04).
- parrying an unarmed attacker with a weapon stays vanilla: the punch bounces off, no damage, no stamina. Legacy's code makes that parry fail (the attacker recoils, Geralt takes the punch and pays the parry); its comment describes the opposite case (an unarmed Geralt parrying a weapon), which vanilla's `FistFightCheck` already refuses, so the change looks like a misreading, and the changelist does not mention it (project owner, 2026-10-04).

## [DIFF-04 Enemy scaling options](diff.md#diff-04-enemy-scaling-options)

- all scaling options apply at once; legacy's list missed the progressive and boss options, which waited for Geralt's next level-up (owner, 2026-10-29)
- a random level survives saving and loading: an enemy restored from a save keeps the level a random scaling type gave it at its next level computation (the start of a fight), until a scaling option or the mode changes or its level falls outside the bounds as Geralt levels. Legacy reset it at every spawn, a load included, so every reload rolled each saved enemy's level again at the start of the next fight (porter's call 2026-10-30, confirmed by the owner, 2026-10-31)
- with the menu never opened, every unset scaling option takes the "Recommended" preset's value: soft upscaling (enemies more than 6 levels below Geralt raised to 6 below), nothing else (no extra health or damage, no progressive level bonuses). Legacy's code read unset options as no scaling, though its readme told players to apply the recommended presets; the port has been balanced and tested with soft upscaling since AI-A (DD1, owner, 2026-10-29).
- the difficulty mode multiplies the menu's health and damage modifiers, which add to each other: (1 + mode) × (1 + enemy + boss), health at least ×0.01, damage at least ×0. Legacy summed them, 1 + mode + enemy + boss, so the modifiers counted the same on every mode and could take enemies to no health or a negative damage factor on the lower modes; "Death March!" with the "Hardcore" preset now gives a boss ×5 health and ×7 damage (legacy ×3.5 and ×4.5) (DIFF audit F3, owner, 2026-10-31)
- the boss modifiers (and AI-01's rule of no "High" or "Deadly" ability for bosses) follow the boss bar: an NPC's bonuses are recomputed when the boss bar or the quest tag function adds or removes its boss tag, so story bosses whose bar appears in the fight get them during it and lose them when it goes. Legacy read the tag only when the level was computed, so story bosses never got them unless Geralt levelled up, or an option or the mode changed, while the bar was up (DIFF audit F2, owner, 2026-10-31: "fix it so the scaling options affect bosses like a user would expect"). The recompute keeps the NPC's current level (the level a scaling type or a script gave it), not a full reset of the level; and the quest function `HealthBarVisiblityQuest` counts as a boss path, next to the boss bar's own `OnShow` and `OnHide` (two porter's calls, confirmed by the owner, 2026-10-31)

## [SKL-01 Skill system rules](skl.md#skl-01-skill-system-rules)
