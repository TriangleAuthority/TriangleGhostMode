**How the work runs** (as agreed with the project owner):

- One small slice at a time: read the legacy units (`git show master:` vs `legacy-GM:`, 5.x in `vanilla-5.x:`), port with wrappers where possible, add a `gmtest_*` function, build, test in game, update the feature entry and this page.
- `tools/build_mod.py --ref 5.x-GM` builds the **committed** branch: commit on `5.x-GM` (worktree `../TGM-5x-GM`, next to this checkout) before building; amend while iterating. Docs live on `master` (this checkout).
- Commit and push only when the project owner says so; at the end of a slice, report the result and ask.
- The first version reproduces legacy's behaviour, gaps included; improvements go to the feature's **Later** list ([why](../feature-mapping.md#legacy-behaviour-first)).
- Scripted input and its limits (held keys, the heavy attack, bombs), the probes and the test save: [game-automation.md](../game-automation.md). If the game hangs on "Loading" after loading a save, check that it runs on the dedicated GPU (same doc). Minimizing the Claude window to bring the game to the front is allowed.
- When a feature is finished, run the regression check in one game session (`gmtest_regress()` plus the panel check; see [development.md](../development.md#testing-in-game)) and add the feature's situation-free checks to it.
- Ghost Mode supports both skill trees: a feature that touches skills is ported and tested for the classic and the new tree ([feature-mapping.md](../feature-mapping.md#two-skill-trees)).
- A finished feature is audited by a new session that did not port it, then signed off ([audit](../feature-mapping.md#audit-signing-a-feature-off)).
- Feature entries follow the [template](../feature-mapping.md#feature-entry-template): short table values, verification per slice (real or scripted), open checks; measurements and investigations stay out of the repository docs.
- `python tools/unit_sweep.py <keyword> --unattributed` checks a mapping for missed units.
- Ghost Mode ships a script blob but must stay portable to loose scripts ([development.md](../development.md#principles)): `@replaceMethod` rather than a scope-based override where both work, every changed line marked `//modSigns`, no native wraps without the project owner's agreement; `python tools/check_modsigns.py` checks the last two before each script commit.
- Anything that fits no slice, feature, area or pillar goes into the misc bucket, [misc.md](misc.md), instead of being dropped or forced into a feature.
