## Where the port stands

**Every area is ported and signed off by the owner** (the last, FIX and HORSE, on 2026-11-03): every legacy change is accounted for (the [sweeps](sweep/) left no unattributed unit), each area was audited by a session that did not port it, and a whole-port audit followed (2026-11-03). The [area table](#areas) links each area's entries.

**Game build:** the port is **verified** on 5.0 Steam build 26238013 (`witcher3.exe` 5.0.0.1090142): the regression passes in both trees. What that patch changed for Ghost Mode is in [game-5.0-changes.md](../game-5.0-changes.md).

**The skill trees:** both are supported. The classic tree is legacy Ghost Mode's tree; the new tree is 5.x's, adapted (legacy's skills on 3 levels, scaled tiers, a few new designs by the owner). The classic tree is the default: Ghost Mode's own option `GMClassicSkillTree` (Options → Mods → Ghost Mode, gameplay group) defaults to true ([SKL-02](skl.md#skl-02-skill-tree-option), [two skill trees](../feature-mapping.md#two-skill-trees)).

**The regression:** `python tools/regress.py --trees both` runs, per tree on a fresh launch of the test save, `gmtest_regress()` (every situation-free check of every area) and `gmtest_panel()` (the character panel and the checks that read the game a frame later); `gmtest_loot()` runs in a launch of its own ([development.md](../development.md#testing-in-game)).

**What is left:**

- **Checks that need a playthrough:** a quest's scene, a contract, days passing, a merchant met in play. They are each feature's **Open checks**; the owner runs them in a playthrough after the first playable version (the owner's decision, 2026-11-02).
- **Checks waiting for the owner:** STAM-07's two listening checks ([stam.md](stam.md#stam-07-low-stamina-heartbeat)) and the look of STAM-10's HUD ([stam.md](stam.md)); the porter's calls not yet confirmed (`python tools/deviations.py --unconfirmed`).
- **Not audited yet:** what the owner added in the new tree after its area's sign-off (STAM-10, exhaustion paid from max stamina; the redesigned new-tree skills of [SKL-03](skl.md#skl-03-fast-attack-branch), [SKL-04](skl.md#skl-04-strong-attack-branch) and [SKL-18](skl.md#skl-18-perks)) is verified by script.
- **Questions for legacy and its author:** the [contradictions between legacy's code and its changelist](../open-questions.md#legacy-data-vs-changelist), the [tests in legacy Ghost Mode](../open-questions.md#to-test-in-legacy-ghost-mode) and the author's answer on [ungated NPC attacks](../open-questions.md#ungated-npc-attacks).
- **Balance passes:** the numbers are legacy's; tuning comes last ([balance.md](balance.md)).
- **New Game+:** carried over and scaled, never tested ([NG+ policy](../feature-mapping.md#new-game-carried-over-and-scaled-not-balanced-or-tested)).

**Code:** the scripts in `modGhostMode/scripts/local/gm/` (by area; `tests/`: the `gmtest_*` exec functions), Ghost Mode's DLC `modGhostMode/files/dlc/dlcghostmode/` (`.reddlc`, `data/gameplay/` with the generated NG+ copies in the `*_plus` folders), whole-file overrides at their vanilla paths under `modGhostMode/files/`, the menu `modGhostMode/menu/modGhostMode.xml`, strings in `modGhostMode/localization/` (9 languages: br, cz, de, en, es, fr, it, pl, ru), sound banks in `modGhostMode/sound/`. How to build, install and test: [development.md](../development.md#build-compile-install), [game-automation.md](../game-automation.md).

**How the work runs** (as agreed with the project owner):

- One small slice at a time: read the legacy units (`git show vanilla-1.32:` vs `legacy-GM:`, 5.x in `vanilla-5.x:`), port with wrappers where possible, add a `gmtest_*` function, build, test in game, update the feature entry and this page.
- `tools/build_mod.py --ref <branch>` builds the **committed** branch: commit before building. Code, tools and docs live together on `master`, or on an area's `gm/<area>` in its own worktree while areas are ported in parallel ([development.md](../development.md#working-in-parallel)).
- Commit and push only when the project owner says so; at the end of a slice, report the result and ask.
- The first version reproduces legacy's behaviour, gaps included; improvements go to the feature's **Later** list ([why](../feature-mapping.md#legacy-behaviour-first)).
- Scripted input and its limits (held keys, the heavy attack, bombs), the probes and the test save (`python tools/game.py run test`): [game-automation.md](../game-automation.md#test-saves).
- Checks that need a save further into the story wait for the owner's playthrough (above); the port goes on without them.
- When a feature is finished, run the regression and add the feature's situation-free checks to it ([development.md](../development.md#testing-in-game)).
- Ghost Mode supports both skill trees: a feature that touches skills is ported and tested for the classic and the new tree ([feature-mapping.md](../feature-mapping.md#two-skill-trees)).
- A finished feature is audited by a new session that did not port it, then signed off ([audit](../feature-mapping.md#audit-signing-a-feature-off)).
- Feature entries follow the [template](../feature-mapping.md#feature-entry-template): short table values, verification per slice (real or scripted), open checks; measurements and investigations stay out of the repository docs.
- `python tools/unit_sweep.py <keyword> --unattributed` checks a mapping for missed units.
- Ghost Mode ships a script blob but must stay portable to loose scripts ([development.md](../development.md#principles)): `@replaceMethod` rather than a scope-based override where both work, every changed line marked `//modSigns`, no native wraps without the project owner's agreement; `python tools/check_modsigns.py` checks the last two before each script commit.
- Anything that fits no slice, feature, area or pillar goes into the misc bucket, [misc.md](misc.md), instead of being dropped or forced into a feature.

## Features with a save impact

Features whose port needs more than installing the mod (see [save compatibility](../feature-mapping.md#save-compatibility)). [ITEM-04](item.md#item-04-items-moved-to-level-scaling): `reacquire items` (expected): an Iris, Ofir armor, Ofir Sabre 2, a piece of Blood and Wine's first vampire set, Yoana's armor, the Nekker boots or the standalone starting gear held from before the mod keeps no fixed damage or armor and has no per-level damage or armor until obtained again; items already owned also keep the level and random bonuses they got (ITEM-02, ITEM-06, ITEM-08). Otherwise none: ARM's changed item stats and tags apply to items already owned (verified, [ARM-01](arm.md#arm-01-armor-pieces-resistances-by-class-armor-by-level)); the Kaer Morhen schematics are granted at load and 5.x's "Starting Armor Upgrade schematic 1" removed ([ARM-12](arm.md#arm-12-kaer-morhen-set)).

Removing the mod from a save is not supported ([save compatibility](../feature-mapping.md#save-compatibility), the owner's decision, 2026-10-18); what it does, as facts for the release notes: mutations researched at legacy's costs show as partly researched under 5.x's costs again ([MUT-01](mut.md#mut-01-mutation-system-research-costs-and-housekeeping)); the Mutation Catalyst and its recipe become unknown items ([MUT-12](mut.md#mut-12-life-leech-and-mutation-catalyst-mutation-11)); the Kaer Morhen pieces disappear from the save, worn ones leaving their slots empty ([ARM-12](arm.md#arm-12-kaer-morhen-set)); the master weaponsmith and armorsmith tools become unknown items, and the items ITEM moved to level scaling (Iris among them) keep only their per-level damage or armor ([ITEM](item.md#save-impact)).
