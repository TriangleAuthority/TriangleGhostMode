# Open questions

Questions about modding 5.x that are not answered yet, with why they matter and how to answer them. Questions a planned pilot slice will answer are listed under that slice in [feature-mapping.md](feature-mapping.md#pilot) instead.

When a question is answered, move the answer into the doc it belongs to (usually [development.md](development.md)), and delete the entry here, noting where the answer went in the commit message.

## Several mods with script blobs

**How does the game merge the script blobs (`precompiled.rsblob`) of several mods?**

Each blob is compiled against the vanilla scripts only, so blobs are built without knowing about each other and the game must merge them at startup. What we have:

- The executable names wrappers `%s@%s@wrapper%03d` and has a "maxWrapping index reached" error, so `@wrapMethod` wrappers from several mods most likely chain.
- It reports "@replaceMethod duplicate found for '%s'"; unclear whether that is an error or last-one-wins between separate mods.
- Mods may not give new enum members explicit values, which suggests the game numbers them at load time.
- Two blob mods that wrap *different* methods load together and both work (`modAutomation` plus the pilot build, [game-automation.md](game-automation.md#two-script-blobs)).
- The [mod.io guide](https://mod.io/g/the-witcher-3/r/what-does-the-remaster-mean-for-modding) states: when several mods' blobs change the same function or enum, the highest priority in `mods.settings` wins (default alphabetical: numbers, underscore, letters), and a blob's change beats loose scripts for the same function whatever the priority. Tested 2026-10-04 at equal priority: Ghost Mode's `@replaceMethod` of `W3PlayerWitcher.ReduceDamage` beat both a loose mod and another blob (`modGMMergeTestBlob`), silently. Still open: does a priority change flip it, and which end of the order wins; do wrappers from several blobs chain.

**Why it matters:** if overrides are winner-take-all, any other mod overriding a function Ghost Mode overrides silently drops one of the two changes. That decides how strongly to prefer `@wrapMethod` over overrides, and what priority Ghost Mode should recommend. It also decides what "higher priority" means in `mods.settings` (lower or higher number).

**How to answer:** two throwaway blob mods (`modGMTestA`, `modGMTestB`) that clash on purpose: both wrap the same method (do both run, in what order?), both override the same method in a scope block (which wins; does swapping their priorities flip it?), both add an enum member (distinct values, no error?). One build, two game launches (one per priority order); `tools/game.py` makes each launch a short scripted run.

## Scripts

- **Struct fields.** Can a blob add fields to a vanilla struct (re-declaring the struct, like a class)? Loose scripts reject it ("already exported and 'isMod' is false").
- **State overrides in game.** A scope-based override of a state (`state CombatFists in W3PlayerWitcher extends Combat { ... }`) compiles; not yet run in game. Wrapping a state function is verified.

## Install and testing

- **Mods without a `mods.settings` entry.** The wiki says mods in `<game>\mods` are enabled by default; ours has always had an entry. Test by removing the entry once.

## Legacy design intent

<a id="ungated-npc-attacks"></a>
- **Ungated NPC attacks (STAM-08).** Ghost Mode charges every NPC attack (the light-attack cost unless the behaviour tree names another), but an attack is only refused for lack of stamina where its task checks stamina, and some do not, in legacy as in the port. They start below their cost and leave the NPC at 0. (1) 41 attack tasks whose behaviour tree turns `checkStats` off (all free in vanilla, so the setting did not matter before Ghost Mode gave them a cost): Blood and Wine monsters (the panther's whole melee set; the bruxa; Dettlaff, his vampire form and tornado; the shaelmaar's melee and projectile; the banshee; the barghest's fire breath and counter; the fairytale witch's projectiles; the ep2 giant's ground trap; a death-bruxa spawn's projectile) and scripted boss tactics (Olgierd's sand attack, shadow dash, shadow step, a melee attack and his counter moves; the same set in the "ethereal" tactic; Gregoire's five attacks). Six more tasks with the check off are counterattacks (`EAT_Attack20`: Imlerith's two, the generic human counter-push's four); legacy's rule re-enables the check for every counterattack, so those are gated, which looks deliberate. (2) 13 attack task classes whose `IsAvailable` skips the check (charges incl. the fiend's, Dettlaff's dash, the ice giant's icicles, two magic attacks, synced-animation attacks, projectile attacks incl. archers, summons, bomb throws). Legacy never mentions them and changed none of these trees or classes, but it did re-tune most of these enemies' stamina values individually (the light-attack cost these attacks pay: panther and banshee 10 → 20, bruxa, shaelmaar, fairytale witch, giants and Gregoire 10 → 16; Dettlaff kept at 10 with cheaper parry and counter, 10; barghest kept at 20; Gregoire's free parry and counter now 20; Imlerith's −20 parry and counter discount removed; regen raised for all), so the author balanced these fights with their attacks charged but never refused, whether or not she knew they were ungated. The tree cases are almost all signature boss and monster moves, which suggests CDPR let set-piece moves ignore stamina in vanilla. Per enemy tree, most enemies are mixed, with a few signature moves ungated (bruxa 41 gated / 7 ungated, shaelmaar 18/3, ep2 giant 13/1, Dettlaff's vampire form 12/2, fairytale witch 10/2, Olgierd's tactics 8/4, "ethereal" 7/4, barghest 5/3, fiend 4/2, banshee 2/2, Dettlaff 2/1); entirely ungated are the panther (0/5) and Gregoire's tactics (0/5; his counter tree is gated); fully gated are e.g. Imlerith, the werewolf, the big bad wolf, ghouls, the ice giant's main tree and wolves. Asked the author (2026-10-03); the project owner resolves this entry when she answers. **Open:** did the author mean every attack to be refused without stamina (then these are oversights, closed by checking the cost directly at the attack's start), or are some deliberately ungated? Asking the author, or reading her other notes, would settle it. Until then the port keeps legacy's behaviour. Details in [stam.md](features/stam.md#stam-08-npc-stamina).

## Mod scripts

- **Repeated loot-list calls crash the game (found 2026-10-24).** `AddItemsFromLootDefinition`, repeated on one inventory in one launch, ends in an access violation in 5.x's engine (sooner with Ghost Mode's data; with Ghost Mode off, a hang after some hundreds of calls). The player-reachable cause is fixed: CRAFT-10's Yoana wrapper queued her master list at every opening of her shop after her quest and crashed the game at its 14th to 16th opening; since 5.x-GM `e2273a6e` it adds the list's entries by `AddAnItem` ([CRAFT-10's deviation](features/craft.md#craft-10-master-kits-at-the-master-craftsmen), owner, 2026-10-24; 45 and 42 openings in one launch without a crash). No other script of Ghost Mode's calls it in play; merchants' normal restocks did not crash (240 in one launch). The engine fault remains for tests that roll lists repeatedly (LOOT's `GMTestLootRoll`, modAutomation's `autolootroll`): `gmtest_loot()` runs in a launch of its own. Open: nothing to decide; reopen if a crash is seen in play. Details: [game-automation.md](game-automation.md#setting-up-geralt-and-the-world).

## To test in legacy Ghost Mode

Questions about how legacy Ghost Mode (1.32) actually played that its code leaves open. The port has decided each one; the project owner plans to reinstall legacy and test them together. An answer that differs from the port's decision goes back to the owner.

- **Parry without stamina: staggered? (DEF-05, STAM-03).** Legacy's code adds a stagger to a parry without enough stamina of a parryable attack, but vanilla's `ProcessActionBuffs` skips every effect of such a hit, so the stagger seems never to have applied: 50% damage only. The port applies the stagger (project owner, 2026-10-04). Test: guard at 0 stamina against a wolf's bites; is Geralt staggered?
- **Unparryable attacks that knock down or stagger, parried (DEF-05).** Legacy's code skips the partial parry for attacks carrying a knockdown, heavy knockdown, stagger, long stagger or knockdown applicator, zeroes their damage (it dropped `CanBeParried` from `CActor.ReduceDamage`'s parry branch) and still applies their effects (only parryable attacks are exempt from them). The port follows that code (project owner, 2026-10-04). Test: guard against a heavy unblockable slam that knocks down (e.g. a troll's or a fiend's) and one that staggers; any damage? knocked down or staggered?
- **Armed Geralt parrying an unarmed attacker (DEF-05).** Legacy's `PerformParryCheck` makes this parry fail (the attacker recoils, but Geralt takes the punch and pays the parry), while its comment speaks of parrying a weapon with fists. The port keeps vanilla: the punch bounces off, no damage, no stamina (project owner, 2026-10-04). Test: guard with a sword against an unarmed brawler; does Geralt take damage?
- **A counter's effects (DEF-06).** Vanilla's code, and legacy's, applies a countered attack's effects (bleeding, for example) although the hit deals no damage: attack actions keep "apply effects without damage" on, and only parried hits are exempt. The changelist says a counter prevents all negative effects; the port blocks them. Test: counter a bleeding-inflicting attack (e.g. a drowner's or a bandit's sword); does Geralt bleed?
- **Countering an unparryable attack that knocks down or staggers (DEF-06).** As for parries, legacy's code gives no partial counter, no damage, and the attack's effects. The port follows that code (project owner, 2026-10-04). Test: counter a heavy unblockable attack; any damage, knocked down?
- **Muscle Memory on counters (DEF-07).** The changelist says all light-attack bonuses apply to counters, but in legacy's code Muscle Memory's attack power (`sword_s21`) does not reach a counter (its bonuses are tied to the `attack_light` tag and to basic attack types). The port counts counters as fast attacks and gives them Muscle Memory's attack power, once ([SKL-03](features/skl.md#skl-03-fast-attack-branch), project owner, 2026-10-04, revised 2026-10-11). Test: with Muscle Memory, does a counter hit as hard as a light attack?
- **Attack-power skills counted twice (SKL).** In 5.x Muscle Memory (`sword_s21`) gives a light attack its bonus twice, once by its `attack_light` tag and once in the attack's explicit light-attack check (measured: +0.6 at level 3 for +0.3 in the XML); Strength Training `sword_s4` has the same shape (`sword_2` counts once). 1.32's and legacy's code are the same. The port counts them once at a doubled value, +0.1 per level and +50% at level 5 in the classic tree, as legacy played (SKL's D47, project owner, 2026-10-11). Test: with Muscle Memory at full level, does a light attack's damage rise by twice the skill's stated bonus? Also Strength Training on a heavy attack.
- **In Combat's Fires against enemies (SKL-18).** Legacy's code halves the damage of Geralt's own bombs and bolts whenever he has the perk, whatever the victim; the changelist says it halves the damage he takes from them. The port halves only the damage Geralt takes (D38, project owner, 2026-10-09). Test: with the perk, does a bomb or bolt deal half damage to an enemy?
- **Metabolism Boosts on decoctions (SKL-18).** Legacy's code cuts a decoction's toxicity with the perk too, only without spending the adrenaline; its description, and 5.x's, say decoctions are not affected. The port follows the description: no cut, no adrenaline spent (porter's call). Test: with 3 adrenaline, does drinking a decoction cost its full toxicity?
- **Hits during Undying (SKL-07).** Legacy puts Undying's immortality on its own channel, 256; the engine packs channels as 8-bit flags per mode, so 256 lands in the invulnerable range: in the port (same value) Geralt is invulnerable for the 5 s and hits deal no damage, which leaves legacy's exemption from the hit pause of the healing (ported, SKL audit F1) idle. Legacy's changelist speaks of immortality. Test: get hit during Undying; does Vitality drop (to no less than 1) or not move?
- **Rend's knockdown below 3 adrenaline (SKL-04).** Legacy adds a knockdown applicator to every Rend hit, not only with the 3-adrenaline shock wave; the changelist mentions only the shock wave's knock-back. The port follows the code. Test: does a Rend at 0 adrenaline knock the target down?
- **Iris's phantom strike and blocks (SWD-06).** The changelist (lines 640–641) says the phantom copy's strike goes through shields, blocks and armor. Legacy's code (ported as it is, 2026-10-19) makes the phantom hits undodgeable, destroys shields, ignores armor and resistances and clears the hits' parry flag (`SetIsParried(false)`, as vanilla's phantom strike), so in the code they go through a parry; the NPC may still play its block. ## XML and other data

- **`on_conflict` coverage.** `extend` and `replace` work on abilities, and repeated tags are replaced in order (see [development.md](development.md#fine-grained-xml-overrides-50)). The [mod.io guide](https://mod.io/g/the-witcher-3/r/what-does-the-remaster-mean-for-modding) lists which definition types take it (not recipes, schematics, effects, mutations, skills; effects: a DLC cannot override an `<effect>` entry, verified 2026-10-24 in [development.md](development.md#fine-grained-xml-overrides-50)) and says a tag listed with a leading `-` is removed (verified for item tags, 2026-11-01: an item's `extend` adds the tags it lists and removes those with `-`, and sets the entry's own attributes such as `price`, but empties Hearts of Stone items; [development.md](development.md#fine-grained-xml-overrides-50)). Open: the rest of the list when a feature needs it; does `extend` on an NG+ (`items_plus`) item behave the same? Does a DLC `<reward>` override take `extend` (LOOT-07 uses whole-file copies)? A DLC `<loot>` list only merges into vanilla's (answered 2026-10-22, [development.md](development.md#fine-grained-xml-overrides-50)). A DLC cannot override a schematic (ARM-12): CRAFT's DC1.
- **NG+ and DLC overrides.** In New Game+, does the game read only a DLC's NG+ mounter (`abilities_plus\`), or its regular one too (and then which wins)? Ghost Mode mounts both, as vanilla DLCs do ([development.md](development.md#fine-grained-xml-overrides-50)), so either way NG+ gets Ghost Mode's rules; only the scaling of a few values could differ. NG+ is not tested ([feature-mapping.md](feature-mapping.md#new-game-carried-over-and-scaled-not-balanced-or-tested)); a probe in an NG+ save, if one ever exists, would settle it. The same probe would show whether an `extend` item entry in `items_plus\` works as it does in `items\` (ECON's slice E2 gives every NG+ item entry whole for want of it; 2026-11-01).
