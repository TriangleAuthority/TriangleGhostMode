# Legacy Ghost Mode: versions, dependencies, packaging

## Versions on `legacy-GM`

`legacy-GM` has three commits on top of `master`:

1. **Shared Imports v0.6**: a dependency (see below), merged into `modGhostMode/scripts`.
2. **Community Patch – Base v1.0**: a dependency (see below), merged into `modGhostMode/scripts`.
3. **Ghost Mode 4.1**: the packaged Nexus release (mod 992, file version 4.1, 2020-08-24; its own readme still says v4.0), unpacked with `tools/unbundle.py` and converted to UTF-8. This is the canonical legacy version. It also includes the history of the original GitHub repository this project was forked from (77 commits, Oct 2017 – 14 Aug 2020, subjects listed in the commit message), which was a slightly older v4.0. Because the dependencies come first, this commit contains only Ghost Mode's own changes.

Besides the mod's files, the commit includes:

- `modGhostMode/content/texture.cache` (a replacement icon, `gameplay\gui_new\icons\skills\sword\sword_s10.png`) and `modGhostMode/content/soundspc.cache` (one Wwise sound bank), kept in their packed form.
- `design-docs/release/`: the release's `Readme.txt`, `ModDescription.txt` and `FullChangelist.txt` (plus Russian versions). The English description and changelist are also on `master` as [legacy-ModDescription.txt](legacy-ModDescription.txt) and [legacy-FullChangelist.txt](legacy-FullChangelist.txt). **The changelist is the most complete description of what Ghost Mode changes**, feature by feature. Start there when deciding what to port.

## Dependencies

Since v4.0 Ghost Mode requires two other mods "to compile properly" (release readme):

- **Community Patch – Base**
- **Community Patch – Shared Imports**

Ghost Mode's scripts call functions and properties defined in those mods, which are not part of vanilla.

- **Shared Imports v0.6** (Nexus mod 2110) is included on `legacy-GM` as its own commit. It declares engine class properties and functions for scripts: it extends `scripts/engine/components.ws` and `scripts/engine/environment.ws` and adds `scripts/local/*.ws` (13 files). **Game version 5.0 has it built in**: 5.0 adds the same 13 classes as `scripts/engine/C*.ws`, and its `components.ws`/`environment.ws` contain the same additions. The port does not need it, and `scripts/local/` should not be carried over.
- **Community Patch – Base v1.0** (Nexus mod 3652) is included on `legacy-GM` as its own commit. It replaces 16 vanilla 1.32 scripts to make Steam, GOG and GOTY scripts identical (random main menu, the GOTY NG+ item level fix, no "DLC installed" pop-ups, a "Downloadable content" menu entry) and adds basic support for community-made hubs; `temp.ws` and `dlcManager.ws` only differ in formatting. **Ghost Mode was written on top of it**: its `r4Game.ws`, `types.ws` and `ingameMenu.ws` contain all of the patch's additions. (Its `definitionsManager.ws` has 4 of the patch's 8 added lines.)
- **5.0 contains most of Community Patch – Base**: all of its changes to `definitionsManager.ws`, `r4Game.ws`, `commonMainMenuBase.ws`, `mainCreditsMenu.ws`, `hudModuleTimeLapse.ws`, `menuBase.ws` and `popupBase.ws`, and part of `ingameMenu.ws`, `igmOptions.ws` and `r4guimanager.ws`. Missing from 5.0 are mainly the hub-support changes: `areaTypes.ws` (72 added lines), `types.ws` (79) and `igmStructureCreator.ws` (3). Ghost Mode's `types.ws` carries those hub changes, so decide during the port whether they are needed.
- The patch also ships a dummy `mod0000____CompilationTrigger` mod that only forces script recompilation; it is not included.

The readme also lists merge rules for other mods (Preparations, Nitpicker's Patch, Besserwisser's Patch, All NPC Scabbards, Better Icons) and credits several contributors whose fixes are included (KoalaNalle's w2ent fixes, W3EE collision fixes, Generic Merchants Fix, and others).

## How the release was packaged

- `modGhostMode/content/blob0.bundle`: all XML, CSV and binary files (legacy bundle format, LZ4HC compression).
- `modGhostMode/content/scripts/`: loose scripts (UTF-16).
- `modGhostMode/content/*.w3strings`, `modGMTutorials/content/*.w3strings`: compiled string tables, generated from the `localization/` CSVs (not kept here).
- `modGhostMode/bin/config/r4game/user_config_matrix/pc/modSignsConfig.xml`: the options menu (copied into the game's `bin` folder on install).
- `metadata.store`: generated by the packer (not kept here).
- The binary files in the bundle are CR2W version 163 (cooked by the packer); the repository's W3Edit-saved copies are version 162 but have the same content.

Packaging quirks:

- `dlc/dlc3/.../quest_levels.csv` and `dlc/dlc12/.../quest_levels.csv` are stored in the bundle as zero bytes, so the release shipped them broken. The repository copies are identical to vanilla, so Ghost Mode did not mean to change them; they were kept.
- The menu XML declares `encoding="UTF-16"` but is plain ASCII. The repository copy declares UTF-8.

## Where the mod lives once installed

Everything Ghost Mode installs goes into the game folder:

- `Mods\modGhostMode` and `Mods\modGMTutorials`: the mod itself.
- `bin\config\r4game\user_config_matrix\pc\modSignsConfig.xml`: the options menu.
- Dependencies: Community Patch – Base overwrites scripts in `content\content0\scripts` and adds `Mods\mod0000____CompilationTrigger`; Shared Imports is `Mods\modSharedImports`.

It installs nothing outside the game folder, but it leaves data in two places at runtime:

- **`Documents\The Witcher 3\user.settings`**: the game stores options menu values here, including Ghost Mode's 38 settings (groups such as `GMGameplayOptions` and `GMScalingOptions`). On first run `gm_generic/gm_options.ws` writes Ghost Mode's defaults there via `GetInGameConfigWrapper().SetVarValue`.
- **Save games**: Ghost Mode's facts, saved script variables, skill and character-development state, and item stats are stored in saves. That is why the release docs require the `cleardevelop` console command when starting from a vanilla save or after uninstalling, and warn that crafted items keep their modded stats.

It does not change `input.settings`: every input action its scripts use already exists in vanilla, so it needs no new key bindings. *Unverified for the port*: how 5.x stores options menu values, and how custom menus like `modSignsConfig.xml` interact with 5.x's built-in mod menu (`gui/menus/modMenu.ws`).

## Effect on the vanilla baselines

The vanilla file set is defined by the paths under `modGhostMode/files`. Ghost Mode 4.1 has 12 paths that the original repository did not: entity templates for the Blood and Wine tournament contestants (`dlc/bob/data/quests/sidequests/quest_files/sq701_tournament/characters/contestants/*.w2ent`). They were added to both baselines afterwards:

- `master` includes their legacy versions, extracted from the legacy game copy (`DLC\bob\content\bundles\blob.bundle`, zlib-compressed; see [tools.md](tools.md#game-install)) with `tools/unbundle.py`.
- `vanilla-5.x` includes their 5.0 versions (from `bob.bundle`, by running `tools/extract_vanilla.py` from a `legacy-GM` checkout).
- Every file the original repository shipped is also in 4.1; nothing was removed.
